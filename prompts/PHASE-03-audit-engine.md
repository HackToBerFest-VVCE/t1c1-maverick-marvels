# Phase 3 — The deterministic audit engine

**Goal:** the maths, in plain Python, with hand-computed tests. No model calls.
This is the part that makes every rupee figure defensible.

---

## Prompt

```
Read CONTEXT.md §6 for the authoritative formulas.

Build the deterministic audit engine. NO model calls anywhere in backend/audit/
— the package must import and pass tests with GEMINI_API_KEY unset.

backend/audit/engine.py — pure functions, full type hints:

  compute_wage_due(days_worked, notified_rate_paise) -> int
  compute_unpaid_wages(wage_due_paise, credited_paise) -> int
  compute_delay_days(muster_close_date, credit_date) -> int
      # max(0, days_between - 16)
  compute_delay_compensation(unpaid_paise, delay_days) -> int
      # unpaid * 0.0005 * delay_days
      # Decimal throughout, ROUND_HALF_UP, rounded to paise ONCE at the end
  check_entitlement_cap(household_days_used) -> int
      # 125 - used, floored at 0
  match_worker_to_muster(name, muster_names) -> MatchResult
      # Levenshtein + transliteration; returns best match, score, and
      # ambiguous=True when the top two are within 0.05

  reconcile(worker_records, muster_records, wage_records, rate_paise)
      -> DiscrepancyReport

Rules:
- Money is integer paise everywhere. A float rupee amount is a bug.
- The ₹300/day floor applies to the notified rate; if a passed rate is below it,
  flag it in the report rather than silently correcting.
- Every discrepancy carries a clause_id for the clause store to resolve.
- Nothing is computed from a record whose `confirmed` flag is False. Raise
  UnconfirmedDataError if asked.

backend/audit/tools.py — the typed tool interface the orchestrator may call.
Thin wrappers over engine.py with JSON-serialisable in/out and docstrings the
model will see. No logic lives here.

backend/clauses/ — sqlite-vec store over ~40 curated VB-G RAM G snippets.
Seed data/clauses.json with the real ones, each with: id, section reference,
verbatim text, plain-language gloss, an 'as of' date. Cover at minimum:
s.5(3), s.20, s.24(d), Schedule I ¶15, ¶25, ¶32, Schedule II ¶1(7), ¶6.
retrieve(query, k) returns snippets; the drafting layer may cite ONLY what this
returns.

Tests — this is the important part. backend/tests/test_engine.py with expected
values written out by hand in the test, never generated by running the code:
- 6 days at ₹300 = ₹1,800 → 180000 paise
- ₹1,800 unpaid, credited 40 days after muster close:
  delay_days = 40 - 16 = 24; compensation = 180000 * 0.0005 * 24 = 2160 paise
  (₹21.60)
- credit on day 16 exactly → 0 days, 0 compensation (boundary)
- credit on day 15 → 0 (boundary, before the window opens)
- a household at 125 days → balance 0, not negative
- a rate below the ₹300 floor → flagged, not corrected
- an ambiguous name match → ambiguous=True, no silent pick
- reconcile() on unconfirmed records → raises UnconfirmedDataError

Run the tests and show me the output.
```
