# AGENTS.md — Saakshi

Always-on instructions for the Antigravity agent working in this repository.

---

## Before you write anything

1. Read `CONTEXT.md` end to end. It contains the problem, the architecture, the
   maths and the hard constraints. Do not infer any of these from file names.
2. Read `reference/PROBE-RESULT.md`. It records what the Gemini API actually
   supports for Gemma 4 on this project's key. If the file does not exist yet,
   you are in Phase 1 — create it. **Never design against the documentation when
   that file disagrees with it.**
3. **Before touching any UI, CSS, chart or layout, load the design skills.** Run
   `/saakshi-dashboard-ui`, and if the design-skill repos in
   `reference/skills-to-install.md` are installed, load those too. Writing UI
   before reading the design rules produces the generic AI dashboard look we are
   explicitly trying to avoid.
4. For a task spanning more than one file, run `/plan` first and show the plan
   before executing.

---

## The governing rule

**The AI reads. The code computes. The human decides.**

- Gemma 4 converts images to structured data, and structured data to prose.
- All arithmetic, date differences and legal thresholds live in
  `backend/audit/engine.py` as plain, unit-tested Python.
- No value is computed from a field the user has not confirmed in the UI.

If you find yourself writing a prompt that asks the model to calculate, total,
compare or decide a number — stop. That logic belongs in the engine.

---

## Models

Only these two model IDs may ever appear in this codebase:

```
gemma-4-26b-a4b-it
gemma-4-31b-it
```

Enforce this in code. `backend/gemma/client.py` must raise on any other model
string before the request leaves the process. Do not add a Gemini fallback, not
even in a comment, not even "temporarily" — a fallback is how a free project
starts getting billed and how a Gemma challenge entry stops being a Gemma entry.

---

## Secrets

- The key is read from the `GEMINI_API_KEY` environment variable. Nowhere else.
- `.env` is git-ignored. `.env.example` is committed with an empty value.
- Never write a key into source, a test fixture, a notebook, a comment, a commit
  message, or a screenshot.
- Never print the key, not even partially masked, in a log line or error.
- Before any commit, check that no staged file matches `AIza[0-9A-Za-z_-]{35}`.

---

## Code conventions

- **Python**: 3.11+, type hints everywhere, Pydantic v2 for all model I/O,
  `pytest` for tests, `ruff` clean.
- **TypeScript**: strict mode on, no `any`, server components by default in
  Next.js, client components only where interaction demands it.
- **No secrets, no network calls, and no model calls inside `backend/audit/`.**
  That package must be importable and testable with no key present.
- Every function in `backend/audit/engine.py` gets a test with a hand-computed
  expected value written in the test, not generated by running the code.

---

## Data

Synthetic documents only. Never commit or test against a real job card, passbook
or Aadhaar number. Mask identifiers in every log line, UI surface and screenshot.

---

## When something does not work

Do not silently work around a failing API feature. Record what failed, with the
exact error string, in `reference/PROBE-RESULT.md`, then implement the documented
fallback from `CONTEXT.md` §4. A quiet workaround becomes an invisible assumption
that breaks on demo day.
